# Deploying the TaskFlow live demo

TaskFlow deploys as **one Docker image** (root `Dockerfile`): the API serves the built web app on the
same origin, so there are no CORS or cross-site cookie issues. The target is a **free Render web service**
described by [`render.yaml`](render.yaml).

> Status: **live at <https://taskflow-dd07.onrender.com>** (deployed 2026-11-13 from this blueprint; every push to `main` redeploys).
> The steps below are how it was set up, for reference or to deploy a copy.

## What the free plan means for the demo

- **No persistent disk.** The SQLite file lives inside the container. On every start the API seeds the demo
  data if the database is empty, and `DEMO_RESET_INTERVAL_MINUTES=60` resets it every hour, so visitors always
  get a clean, believable workspace. The README says the demo resets.
- **Spins down when idle.** Free services sleep after a period without traffic; the first visit after that
  takes a while (typically around a minute) while the container starts.
- **Secrets.** `JWT_SECRET` is generated by Render (`generateValue: true`). It is never committed.
  The demo passwords (`Demo123!`, `Member123!`) are public on purpose and shown on the login page.

## Steps (one time, about 10 minutes)

1. **Push the repository** to `github.com/mikayelvasilyan/taskflow-web-app` (branch `main`).
2. Sign in at <https://dashboard.render.com> (GitHub sign-in is fine).
3. Click **New → Blueprint**.
4. **Connect** the `taskflow-web-app` repository (grant Render access to that repo only).
5. Render reads `render.yaml` and shows one service, **taskflow** (Docker, Free). Click **Apply**.
6. Wait for the first build and deploy (about 3 to 6 minutes). The log ends with
   `TaskFlow API listening on http://localhost:10000 (production)`.
7. Open `https://<your-service>.onrender.com/api/health`. It should return `{"status":"ok", ...}`.
8. Open the root URL, click **Try the demo**, and check the dashboard, a board and the API docs at `/docs`.
9. Put the URL in the README ("Live demo") and in the Upwork entries.

Because `autoDeploy: true`, every push to `main` redeploys automatically.

## Optional settings

| Variable                      | Default in `render.yaml` | Notes                                                          |
| ----------------------------- | ------------------------ | -------------------------------------------------------------- |
| `JWT_SECRET`                  | generated                | Rotate in Render → Environment if needed (signs everyone out). |
| `COOKIE_SECURE`               | `true`                   | Required on HTTPS.                                             |
| `DEMO_RESET_INTERVAL_MINUTES` | `60`                     | `0` turns the hourly reset off.                                |
| `SEED_ON_START`               | `true`                   | Seeds demo data when the database is empty.                    |

`PORT` is set by Render and read by the API automatically.

## Run the same image locally

```bash
docker build -t taskflow .
docker run -p 4000:4000 -e JWT_SECRET="$(openssl rand -hex 32)" taskflow
# open http://localhost:4000
```

## Troubleshooting

- **Build fails on `npm ci`:** make sure `package-lock.json` is committed and matches `package.json`.
- **App starts but login fails on the live URL:** check that `COOKIE_SECURE` is `true` and you are using
  `https://`.
- **"JWT_SECRET is required":** the env var is missing; re-apply the blueprint or add it under Environment.
